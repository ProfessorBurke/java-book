    Section 7.3 Array Algorithms & Sajaniemi’s Variable Roles

    Subsection 7.3.1 Variable Roles, Revisited

    In Section 4.3 we saw that there are several common loop types, and each takes one or more variables through a pattern of values as the loop executes. We classify the patterns as variable roles, based on Jorma Sajaniemi’s work. The roles we looked at in Chapter 4 are:
    • Stepper: A variable that takes on a predictable sequence of values, for example, 0 to 9 in increments of 1.
      🔗
      🔗
    • Most-Recent Holder: A variable that holds the next value in a stream of input, such as the next value entered at the console, or the next value read from a file. If we’re reading records of data, there will be a most-recent holder for each value in the record (e.g., city name, AQI reading, latitude, longitude).
      🔗
      🔗
    • Gatherer / Accumulator: A variable that accumulates value into itself each time through the loop. For example, we might total values by starting a gatherer variable at zero and adding the most-recent holder value to it each time through the loop.
      🔗
      🔗
    • Most-Wanted Holder: A variable that holds the best fit so far for a property we’re interested in, such as smallest number or longest name. Within the loop, we compare the current value of the most-wanted holder to the most-recent holder, and replace the most-wanted holder if the new value is a better fit. We must be sure to initialize the most-wanted holder to either the first value in the data stream or a value that will ensure it is replaced when we encounter the first value in the data stream (such as a very large number if we’re looking for the smallest number).
      🔗
      🔗
    🔗
    We’ve already seen that we can visit each element of an array in order by using a stepper-controlled loop that takes on the array index values, e.g., 0, 1, 2, 3, 4, 5, and 6 for our aqiReadings array. A stepper could also visit in backwards order (array.length - 1 to 0 in increments of -1), or it could visit only some of the values in the array, e.g., from a partition value through length - 1. We’ll see a use for that in an upcoming section on sorting algorithms. Our array algorithms will generally use a stepper to control the loop by taking on the array index values.
    🔗
    When we’re writing a loop that processes an array, the most-recent holder will be arrayName[index], where index is the loop control variable. This is the value at the current index into the array.
    🔗
    We have seen both a most-recent holder and a gatherer used in Listing 7.3. The variable totalAqi is a gatherer. It is initialized to zero before the first loop, and then each time through the loop, we add the value in the most-recent holder—aqiReadings[i]—to totalAqi. We’ve seen this algorithm and variable role before—the only new component is getting used to the most-recent holder being the next element in the array.
    🔗
    Note that when we’re calculating an average of values in an array, as long as the array is full, we can divide by the length of the array. We don’t need to count the number of elements in the input stream.
    🔗
    If we wanted to find the largest value in the array, for example, we would use a most-wanted holder:
    🔗
    assert aqiReadings.length > 0 : "Cannot find largest in a zero-length array.";
int highestAqi = aqiReadings[0];
for (int i = 1; i < aqiReadings.length; i++) {
    if (aqiReadings[i] > highestAqi) {
        highestAqi = aqiReadings[i];
    }
}
    The pattern should be familiar! Note that we can initialize our most-wanted holder to the first value in the array (highestAqi = aqiReadings[0];), so long as the array has at least one value. (If we cannot make this assumption, then we should initialize it to a very small number, such as Integer.MIN_VALUE, but note that if the array is empty, we will end up with a bizarre highestAqi reading of Integer.MIN_VALUE.)
    🔗
    We then loop over the rest of the array—beginning at index 1. Inside the loop, we compare the value in our most-wanted holder to the most-recent holder (if (aqiReadings[i] > highestAqi)), and if the most-recent holder is a better fit (in this case larger), then we assign the most-recent holder to the most-wanted holder (highestAqi = aqiReadings[i];).
    🔗
    🔗

    Subsection 7.3.2 Enhanced for Loops

    Because traversing every element of an array from start to finish is so common, Java provides a streamlined loop syntax designed specifically for visiting collections sequentially: the enhanced for loop (often called the for-each loop).
    🔗
    Here is how we can print all the values in aqiReadings using an enhanced for loop:
    🔗
    for (int reading : aqiReadings) {
    System.out.println(reading);
}
    Read the header aloud as: “For each int reading in aqiReadings…”
    🔗
    The syntax is the keyword for, followed by parentheses, and then the loop body. Within the parentheses, we declare a variable that acts as a most-recent holder, followed by a colon, and then the array name. This variable will hold a copy of each element in the array, beginning with the element at index 0 for the first iteration of the loop, and then the element at index 1 for the second iteration of the loop, etc., through the last element for the last iteration of the loop.
    🔗
    The most-recent holder variable is of the same data type as the array elements. For our aqiReadings array, that data type is int. If we were iterating over an array declared as boolean[], then the type would be boolean; if it were an array declared as String[], it would be String, etc. It is not an index—it is an array element.
    🔗
    Unlike a traditional for loop (where int i; can be declared beforehand), an enhanced for loop always declares a fresh local variable with a scope strictly limited to the loop body.
    🔗
    Notice what is missing compared to a standard for loop: there is no index variable i, no i < aqiReadings.length boundary check, and no i++ updater. Java manages all of that automatically behind the scenes.
    🔗
    You cannot have an off-by-one error with an enhanced for loop. Because Java handles the starting and ending bounds internally, it is impossible to trigger an ArrayIndexOutOfBoundsException.
    🔗
    The enhanced for loop can also be easier to read. When you only need to inspect or total the values in an array, the enhanced for loop removes index clutter and lets you focus on the data itself. In this accumulator loop, the most-recent holder variable is reading:
    🔗
    int totalAqi = 0;
for (int reading : aqiReadings) {
    totalAqi += reading;
}
    The enhanced for loop is a specialized tool for read-only, sequential access. You should not use it when:
    • You need to modify the array elements: The loop variable (reading) holds a copy of the element’s value, not a reference to the array location itself. Writing reading = 0; inside the loop only changes the local copy—the value inside aqiReadings remains completely untouched.
      🔗
      🔗
    • You need the index: Because there is no index variable i, you cannot coordinate with a parallel array like dayNames[i], store a value in the array, or compare adjacent elements.
      🔗
      🔗
    • You need a non-standard traversal: An enhanced for loop always visits every element from index 0 to length - 1. It cannot traverse backward, skip elements, or stop early without extra work.
      🔗
      🔗
    🔗
    In short, use an enhanced for loop when you simply want to read every value from front to back; use a standard index-controlled for loop whenever you need to modify elements, know where an element is located, work with parallel arrays, or compare multiple positions.
    🔗
    🔗

    Subsection 7.3.3 Comparing and Swapping Adjacent Elements

    Many array algorithms require looking at two neighboring elements at the same time—for example, checking whether air quality improved from one day to the next, verifying whether an array is sorted, or rearranging elements into order.
    🔗

    Subsubsection 7.3.3.1 Comparing Adjacent Elements

    Suppose we want to check whether the AQI readings in aqiReadings are strictly increasing (getting worse every single day). We can compare each element aqiReadings[i] with its right-hand neighbor aqiReadings[i + 1], using a one-way flag (isIncreasing) initialized to true:
    🔗
    boolean isIncreasing = true;
for (int i = 0; i < aqiReadings.length - 1; i++) {
    if (aqiReadings[i] >= aqiReadings[i + 1]) {
        isIncreasing = false;
    }
}
    Look closely at the loop’s stopping condition: i < aqiReadings.length - 1.
    🔗
    Why do we subtract 1 from the length here? Because inside the loop body, we access aqiReadings[i + 1]. For our 7-element array, the last valid index is 6. If we allowed i to reach 6, the expression aqiReadings[i + 1] would evaluate aqiReadings[7] and crash with an ArrayIndexOutOfBoundsException! Stopping at i < aqiReadings.length - 1 ensures that the final pair compared is aqiReadings[5] and aqiReadings[6].
    🔗
    (Alternatively, you can start the loop at i = 1 with i < aqiReadings.length and compare aqiReadings[i - 1] with aqiReadings[i]—both approaches compare every adjacent pair safely.)
    🔗
    🔗

    Subsubsection 7.3.3.2 Swapping Two Elements

    When sorting or rearranging data, we often need to swap the values stored in two array locations, such as aqiReadings[i] and aqiReadings[i + 1].
    🔗
    A common beginner mistake is trying to swap two variables directly in two lines:
    🔗
    // BUG: Overwrites aqiReadings[i] before its value is saved!
aqiReadings[i] = aqiReadings[i + 1];
aqiReadings[i + 1] = aqiReadings[i];
    If aqiReadings[i] held 68 and aqiReadings[i + 1] held 45, the first line copies 45 into aqiReadings[i]—destroying 68 forever. The second line then copies 45 back into aqiReadings[i + 1], leaving both slots holding 45.
    🔗
    To swap two values safely, you must use a temporary variable (temp) of the same data type as the array elements. Think of swapping the liquids in two full glasses: you need a third empty glass to hold one liquid temporarily while you pour.
    🔗
    // CORRECT: Three-step swap using a temporary variable
int temp = aqiReadings[i];
aqiReadings[i] = aqiReadings[i + 1];
aqiReadings[i + 1] = temp;
    Tracing this step by step with 68 at index i and 45 at index i + 1:
    1. temp saves a copy of 68.
      🔗
      🔗
    2. aqiReadings[i] is overwritten with 45.
      🔗
      🔗
    3. aqiReadings[i + 1] receives the saved 68 from temp.
      🔗
      🔗
    🔗
    This three-line swap pattern is a fundamental building block that we will use repeatedly when we implement sorting algorithms later in this chapter.
