    Section 4.6 Nested Loops

    So far, all the loops we have written have been one-dimensional: a single loop control variable steps through a sequence of values to repeat an action.
    🔗
    However, many real-world computing problems are inherently two-dimensional or multi-dimensional:
    🔗
    • Displaying a table with rows and columns.
      🔗
      🔗
    • Scanning through a digital image made of pixels arranged in a grid of width and height.
      🔗
      🔗
    • Inspecting every square on a chessboard or coordinate grid.
      🔗
      🔗
    • Processing data across multiple days, where each day contains multiple hours.
      🔗
      🔗
    To handle multi-dimensional repetition, Java allows you to place one loop inside the body of another. This construct is called a nested loop.
    🔗

    Subsection 4.6.1 The Mechanics of Nested Loops

    In a nested loop structure, we refer to the enclosing loop as the outer loop and the loop inside it as the inner loop. Listing 4.11 demonstrates this relationship with a simple nested while loop:
    🔗
    In Listing 4.11, notice where each control element lives:
    🔗
    • The outer loop initializes row on line 7, tests row < 3 on line 8, and increments row on line 14.
      🔗
      🔗
    • The inner loop is completely enclosed within the body of the outer loop: it initializes col on line 9, tests col < 4 on line 10, and increments col on line 12.
      🔗
      🔗
    When this program runs:
    🔗
    1. row is initialized to 0, and the outer condition 0 < 3 evaluates to true.
      🔗
      🔗
    2. Execution enters the outer loop body and hits line 9: int col = 0;.
      🔗
      🔗
    3. The inner condition 0 < 4 is true, so the inner body executes, printing 0, 0 and incrementing col to 1.
      🔗
      🔗
    4. Crucially, control now returns to the top of the inner loop (line 10). The inner loop continues running until col reaches 4, at which point col < 4 becomes false.
      🔗
      🔗
    5. Once the inner loop finishes, execution advances to line 14: row increments to 1.
      🔗
      🔗
    6. Control returns to the top of the outer loop (line 8). The condition 1 < 3 is true, so execution enters the outer loop again.
      🔗
      🔗
    7. Line 9 executes a second time: col is re-declared and reset back to 0, starting the entire inner loop over from scratch.
      🔗
      🔗
    This flow of control is easy to see in a nested while loop because you can physically see line 9 sitting inside the outer loop’s body.
    🔗
    The exact same flow of control occurs if we rewrite this using for loops:
    🔗
    for (int row = 0; row < 3; row++) {        // Outer loop
    for (int col = 0; col < 4; col++) {     // Inner loop
        System.out.println(row + ", " + col);
    } // inner for
} // outer for
    When reading a nested for loop, you must remember that whenever execution re-enters the inner loop from above, its initializer (int col = 0) runs again, resetting the inner counter back to zero.
    🔗
    An intuitive mental model for understanding how control flows through a nested loop is an analog clock:
    🔗
    • The outer loop is the hour hand.
      🔗
      🔗
    • The inner loop is the minute hand.
      🔗
      🔗
    For every single step the outer loop takes, the inner loop must run through its entire, complete cycle from start to finish before the outer loop can advance to its next value.
    🔗
    Because the inner loop runs to completion on every iteration of the outer loop, the total number of times the inner loop body executes is the product of the two iteration counts:
    🔗
    \begin{equation*} \text{Total Iterations} = \text{Outer Iterations} \times \text{Inner Iterations} \end{equation*}
    In Listing 4.11 above:
    🔗
    • The outer loop repeats three times (row = 0, 1, 2).
      🔗
      🔗
    • For each row, the inner loop repeats four times (col = 0, 1, 2, 3).
      🔗
      🔗
    • Therefore, the inner println statement executes \(3 \times 4 = 12\) times.
      🔗
      🔗
    🔗

    Subsection 4.6.3 Producing Tabular Reports (Rows and Columns)

    The most common application of nested loops in early programming is printing formatted tables and grids. This requires combining three distinct output techniques:
    🔗
    • The outer loop controls the rows: Each pass of the outer loop represents one horizontal line of the table.
      🔗
      🔗
    • The inner loop controls the columns: Inside the inner loop, use System.out.print() (or printf) without a newline to print values side-by-side across the current row.
      🔗
      🔗
    • Advance to the next row: Immediately after the inner loop finishes—but still inside the outer loop—call an empty System.out.println() to drop the cursor down to the start of the next line.
      🔗
      🔗

   4    8   12   16   20   24   28   32   36   40

    Subsection 4.6.4 Generating Coordinate Matrices

    Nested loops are equally useful when calculating mathematical or geographic coordinate matrices.
    🔗
    Recall our search-and-rescue drone from Chapter 2. Suppose that instead of flying in a circle, a drone needs to systematically sweep an area divided into a rectangular survey grid. Given a grid of rows and columns, we can generate every inspection point \((x, y)\text{:}\)
    🔗
    int spacing = 20; // 20 meters between inspection points
 
// Sweep through an area: x spans 0 to 60 meters, y spans 0 to 40 meters
for (int y = 0; y <= 40; y += spacing) {
    for (int x = 0; x <= 60; x += spacing) {
        System.out.printf("(%2d, %2d)  ", x, y);
    }
    System.out.println();
}
    This program produces the following output:
    🔗
    ( 0,  0)  (20,  0)  (40,  0)  (60,  0)  
( 0, 20)  (20, 20)  (40, 20)  (60, 20)  
( 0, 40)  (20, 40)  (40, 40)  (60, 40)
    Notice that the outer loop controls y (the vertical coordinate) and the inner loop controls x (the horizontal movement). This matches how we read text: left to right across a line, then down to the next line.
    🔗
    🔗

    Subsection 4.6.5 Common Traps in Nested Loops

    We’ve already busted some of the most common nested loop misconceptions that beginning programmers face:
    🔗
    • Believing the inner loop picks up where it left off, rather than starting over for each iteration of the outer loop.
      🔗
      🔗
    • Mapping the correct loop to rows and columns when iterating over a grid.
      🔗
      🔗
    • Accurately tracing a nested loop execution and predicting the result.
      🔗
      🔗
    • Understanding that nested loop iterations are multiplicative and being able to calculate how many times the inner loop code will execute.
      🔗
      🔗
    There are a few more frequent beginner traps that we’ll cover here.
    🔗

    Trap 1: The Reset Trap (Initializing in the wrong loop).

    One of the most frequent logical bugs occurs when combining a gatherer with a nested loop.
    🔗
    Suppose you want to calculate the sum of each individual row in a grid:
    🔗
    // BUG: 'rowTotal' is initialized in the wrong place!
int rowTotal = 0; 
 
for (int row = 1; row <= 3; row++) {
    for (int col = 1; col <= 4; col++) {
        rowTotal += col;
    }
    System.out.println("Row " + row + " total: " + rowTotal);
}
    This code produces the following output:
    🔗
    Row 1 total: 10
Row 2 total: 20
Row 3 total: 30
    Because int rowTotal = 0; was declared and initialized outside the outer loop, it is never reset to zero when moving to the next row. Row 2’s calculation begins with Row 1’s total already inside it.
    🔗
    If a variable is meant to track something for an individual pass of the outer loop (such as the sum of a single row or an average for a single student), declare and initialize it inside the outer loop, right before the inner loop begins:
    🔗
    // CORRECT: 'rowTotal' resets to 0 at the start of every new row
for (int row = 1; row <= 3; row++) {
    int rowTotal = 0; // Fresh accumulator for this specific row!
 
    for (int col = 1; col <= 4; col++) {
        rowTotal += col;
    }
    System.out.println("Row " + row + " total: " + rowTotal);
}
    🔗

    Trap 2: Updating the wrong counter (the muscle-memory bug).

    When typing a nested for loop, programmers often write the outer loop with i, and then create the inner loop with j. But out of pure habit and muscle memory, their fingers type i++ in the inner loop’s update section:
    🔗
    // DANGEROUS: Updating 'i' instead of 'j'
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 4; i++) { // BUG: Typed i++ instead of j++!
        System.out.print("*");
    }
    System.out.println();
}
    This creates a catastrophic bug:
    🔗
    1. The inner loop checks j < 4.
      🔗
      🔗
    2. But line 2 increments i, not j!
      🔗
      🔗
    3. Because j never increases, j < 4 remains true forever, creating an infinite loop.
      🔗
      🔗
    4. Meanwhile, i leaps ahead wildly, corrupting the outer loop’s counting.
      🔗
      🔗
    Double-check the third clause of your inner for loop header. Ensure the variable being tested in the middle condition matches the variable being modified in the update step.
    🔗
    🔗

    Trap 3: Confusing who controls what (Row vs. column inversion).

    Another common stumbling block is swapping the responsibilities of the two loops.
    🔗
    Suppose a problem asks you to print a grid that is 2 rows tall and 5 columns wide:
    🔗
    * * * * *
* * * * *
    Beginners often look at the numbers 2 and 5 and instinctively write:
    🔗
    // BUG: Produces 5 rows of 2 asterisks instead!
for (int i = 0; i < 5; i++) {         // Thinks 5 = width
    for (int j = 0; j < 2; j++) {     // Thinks 2 = height
        System.out.print("* ");
    }
    System.out.println();
}
    This loop runs the outer loop 5 times, printing 5 tall rows of 2 asterisks. The shape is completely inverted.
    🔗
    Remember that printing to a screen always moves line by line (top to bottom):
    🔗
    • The outer loop dictates how many lines (rows) appear on your screen.
      🔗
      🔗
    • The inner loop dictates how many characters (columns) appear across each line.
      🔗
      🔗
    • To prevent confusion, avoid generic names like i and j for grid problems; naming your counters row and col makes an accidental inversion immediately obvious.
      🔗
      🔗
    🔗

    Trap 4: The name-shadowing trap (reusing the same loop variable name).

    Because loop counters are often named i, beginners sometimes accidentally use i for both loops:
    🔗
    // BUG: Reusing 'i' causes a compiler error or severe logical failure!
for (int i = 0; i < 5; i++) {
    for (int i = 0; i < 5; i++) { // ERROR: Duplicate local variable i
        System.out.print("*");
    }
}
    In Java, declaring int i in the inner loop when i is already active in the outer loop causes a compiler error: “Duplicate local variable i.”
    🔗
    Even if the inner variable wasn’t re-declared (e.g., writing for (i = 0; ...)), the inner loop would constantly reset the outer loop’s counter back to 0, causing an infinite loop.
    🔗
    The best practice is to use distinct, meaningful names whenever possible, such as row and col, hour and minute, or x and y. If you use traditional short names, follow the standard mathematical convention: use i for the outer loop, j for the inner loop, and k for a third nested level.
    🔗
    🔗

    Trap 5: The Computational cost trap.

    Be mindful of how quickly nested loops multiply:
    🔗
    • A single loop running 1,000 iterations takes less than a millisecond.
      🔗
      🔗
    • Two nested loops of 1,000 iterations execute the inner body \(1{,}000 \times 1{,}000 = 1{,}000{,}000\) (one million) times.
      🔗
      🔗
    • Three nested loops of 1,000 iterations execute the body \(1{,}000 \times 1{,}000 \times 1{,}000 = 1{,}000{,}000{,}000\) (one billion) times, which will noticeably freeze a program for several seconds!
      🔗
      🔗
    Whenever you nest loops, keep an eye on your bounds to ensure you are not creating unintended performance bottlenecks.
