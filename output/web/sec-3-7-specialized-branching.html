    Section 3.7 Specialized Branching: The switch Statement and Conditional Operator

    You can accomplish every branching operation with one of the forms of if statement covered in this chapter. However, Java provides two additional branching options that are good choices for specific cases.
    🔗

    Subsection 3.7.1 The switch Statement

    A switch statement is an excellent choice when you need to execute different code based on a specific, discrete value stored in an integer, character, or String variable. For example, your program might need to:
    🔗
    • Process a user selection from a console menu (e.g., 1, 2, 3, or “Save”, “Open”, “Quit”),
      🔗
      🔗
    • Translate a directional keypress in a game (e.g., 'W', 'A', 'S', 'D'),
      🔗
      🔗
    • Map a month number (1–12) to its name or number of days, or
      🔗
      🔗
    • Respond to a status code from a drone or sensor (0 for Idle, 1 for Active, 2 for Low Battery).
      🔗
      🔗
    While you could write a series of if-else-if statements testing == or .equals() for each of these values, a switch statement often provides a much more readable, structured layout. Listing 3.21 uses a switch statement to turn a user’s numbered response into its text meaning:
    🔗
    The switch statement in Listing 3.21 is found on lines 20-39. It selects code to execute based on the value in the variable response, with branches for five specific values (1-5) and a default branch to handle any value that is not 1-5.
    🔗
    Like an if statement, a switch is a compound statement: a statement that is composed of other programming statements.
    🔗
    The syntax is the keyword switch, followed by an expression (often simply a variable) in parentheses. The expression must evaluate to a 32-bit or smaller integer type (byte, short, int, char) or a String. (Some other object types that we haven’t learned yet are also allowed.) In Listing 3.21, the expression is the integer variable response, which we obtained from the user on line 16. The logic of this switch is equivalent to if (response == 1) {…}, else if (response == 2) {…}, etc.
    🔗
    After the expression, we open the switch statement with an open curly brace. It is closed on line 39.
    🔗
    Within the switch, we have a series of case labels—one for each value of response that we want to handle. A case label is composed of the keyword case, a value for response that we want to handle, and a colon. After each case label is the code we want to execute if response is equal to the case value. The value must be a compile-time constant—a literal value or a final variable.
    🔗
    You might notice that the code after each case label is not enclosed in curly braces and that the code following each label ends with the keyword break. This is a critical feature of switch statements that’s different from most other Java constructs.
    🔗
    A switch statement compares the value of the expression after the word switch to each case value, one at a time, until it finds a matching value.
    🔗
    Execution then proceeds with the code following that label until the closing curly brace of the switch is reached, or a break statement is reached. The break statement breaks out of the switch, to the first line of code following the closing curly brace of the switch.
    🔗
    If no matching values are found and there is a default label, then the code following the default label will execute. In Listing 3.21, we must give the variable responseText a value before we print it on line 42—if we don’t, the compiler will flag a “variable not initialized” error and the code won’t compile. Because the user might not enter one of the expected values of 1-5, we must give responseText a default value, either before or within the switch statement.
    🔗
    The default label of a switch statement is the best place to do this, because the switch statement is where the responseText variable is getting a value. This means anybody reading the code can see within this block the value responseText will get for all possible values of response.
    🔗
    The break statement is a critical component of each case. If you forget the break statement within a case, execution “falls through” to the next case and continues until either the closing curly brace of the switch is reached or a break is reached. Consider the following (buggy) variation of the switch code in Listing 3.21:
    🔗
    switch (response) {
    case 1:
        responseText = "not at all likely";
        break;
    case 2:
        responseText = "somewhat unlikely";
    case 3:
        responseText = "neither likely nor unlikely";
        break;
    case 4:
        responseText = "somewhat likely";
        break;
    case 5: 
        responseText = "very likely";
        break;
    default:
        responseText = "(unknown: invalid response)";
        break;
} // end switch
    In this code, if the response variable contains any value but 2, the code will behave as before. But if the response variable contains 2, execution will jump to case 2: within the switch, responseText will be assigned the value "somewhat unlikely", and then because there is no break, execution will fall through to case 3:, and responseText will be assigned the value "neither likely nor unlikely". The break on the next line then breaks execution out of the switch, to the first line of code following the closing curly brace.
    🔗
    Falling through is a feature of a switch statement that allows a programmer to write multiple cases that are handled by the same code. Note that you can’t write a range condition in a switch, e.g. you can’t test for values between 1 and 10. A switch tests for exact values. To handle a few different values with the same code, programmers take advantage of the “fall through” property. For example, suppose we only wanted to tally up the number of people who say they are likely to vote and the number of people who say they are unlikely to vote—then we might write the following code:
    🔗
    int totalLikely = 0;
int totalUnlikely = 0;
switch (response) {
    case 1:
    case 2:
        totalUnlikely++;
        break;
    case 4:
    case 5: 
        totalLikely++;
        break;
} // end switch
    In this code, we want to handle values of 1 and 2 by incrementing the totalUnlikely variable, and we want to handle values of 4 and 5 by incrementing the totalLikely variable. (There is no action to take for any other values.) To do this, we write two case statements followed by the handling code. If response holds 1, case 1: is the entry point and execution “falls through” to the code under case 2:, incrementing totalUnlikely. The value 4 is similar—execution “falls through” to the code under case 5:, incrementing totalLikely.
    🔗
    The “fall through” property is useful, but it is the source of many bugs. Programmers sometimes forget to put a break in, as a switch statement is the only statement in Java that requires a break in normal functioning.
    🔗
    Always check that you have a break after every case, and if you are intentionally falling through, document that with a comment. (We did not include a comment above because there’s no code after case 1: and case 4:, so the intention to fall through is clear.) It is best practice to always put a break at the end of every case—even if it’s the last case in a switch statement or the default case, because the code might be modified to include additional cases.
    🔗
    🔗

    Subsection 3.7.2 The Conditional Operator ?:

    Java’s final selection option is not a statement, but an operator, called the conditional (or ternary) operator. The syntax takes a little getting used to, but the conditional operator allows us to write concise expressions for choosing between two values.
    🔗
    In Subsection 3.3.1, we introduced if-else statements with the following code:
    🔗
    if (score >= 60) {
    result = "pass";
} else {
    result = "retake";
}
    This code is an excellent candidate for the conditional operator. With it, we can achieve the same result (assigning either "pass" or "retake" to result based on the value in score) in a single line:
    🔗
    result = (score >= 60) ? "pass" : "retake";
    Let’s break it down.
    🔗
    The conditional expression (score >= 60) ? "pass" : "retake" is to the right of the assignment operator. It evaluates to a single value, which is then assigned to result.
    🔗
    Once you are accustomed to reading the conditional operator, the advantage is not just brevity, but clarity. It is immediately obvious that this line is purely an assignment to result.
    🔗
    The operator takes three operands, which is why it is called a ternary operator (unlike a unary operator like - or ++, or a binary operator like * or &&):
    🔗
    1. The Boolean expression is any expression evaluating to true or false. While the parentheses are optional in Java, including them is good practice for readability.
      🔗
      🔗
    2. The ? separates the condition from the true branch.
      🔗
      🔗
    3. The true branch (expressionIfTrue) is evaluated only if the Boolean expression is true.
      🔗
      🔗
    4. The : separates the true branch from the false branch.
      🔗
      🔗
    5. The false branch (expressionIfFalse) is evaluated only if the Boolean expression is false.
      🔗
      🔗
    In our example, if score >= 60 is true, then the entire expression evaluates to "pass". If it’s false, then the entire expression evaluates to "retake". Either "pass" or "retake" is assigned to result.
    🔗
    Because this is an expression that yields a value, you can use it anywhere an expression of that resulting type is valid. Common patterns for ternary operator include pluralization:
    🔗
    String output = "You are " + age + ((age == 1) ? " year old." : " years old.");
    Finding minimum or maximum values:
    🔗
    int max = (a > b) ? a : b;
    Ensuring values are within a safe or valid range (called “clamping”):
    🔗
    int speed = (currentSpeed > SPEED_LIMIT) ? SPEED_LIMIT : currentSpeed;
    And selecting an argument to a method call without having to store the result in a variable first:
    🔗
    displayStatus(isOnline ? "Active" : "Offline");
    In these examples, the true and false expressions of each conditional expression evaluate to the same type. Both the true and false expressions must produce compatible types. For example, if you assign the result to an int, both branches must produce integers. If you mix numeric types, Java applies standard widening rules:
    🔗
    // baseSalary is widened to double if needed
double value = (bonusEligible) ? baseSalary * 1.1 : baseSalary;
    For readable code, avoid nesting conditional operators inside one another (e.g., a ? b : c ? d : e). While syntactically legal, nested ternary expressions are notoriously difficult to read; stick to a standard if-else or switch structure when dealing with more than two possible outcomes.
